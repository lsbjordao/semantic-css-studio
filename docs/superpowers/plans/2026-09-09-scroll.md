# Scroll — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make scroll styling a first-class feature of the exported theme — bar, behavior, anchors and snap — together with the reduced-motion and print blocks.

**Architecture:** The scroll tokens already exist in the schema since the previous delivery, emitted on `:root` but with no consumer. This delivery adds a compiler module that consumes them, generating the per-target bar rules with the `@supports` gate that separates Chromium/WebKit from those with only the standard properties; a separate module for the reduced-motion and print blocks, both emitted **outside** any layer; and the Scroll panel in the editor, with a built-in scrollable sample.

**Tech Stack:** TypeScript 5.8, React 19, Zustand 5, Vite 7, Vitest 3, Playwright 1.55.

**Spec:** `docs/superpowers/specs/2026-09-08-css-editor-expansion-design.md` — "Scroll tokens", "Scrollbar compatibility" and "Reduced motion" sections.

## Global Constraints

- Invariants 1 through 6 of `docs/ARCHITECTURE.md` remain. In particular: `src/compiler/**` does not import React nor use browser APIs (`document`, `window`, `localStorage`).
- Generated CSS is deterministic: same theme, same bytes. Every compiler test must be able to compile twice and compare.
- Declarations are ordered alphabetically by kebab name within each rule; selectors follow canonical domain order and then `localeCompare`.
- Browser target of the generated CSS: Chrome/Edge 99+, Firefox 97+, Safari 15.4+ (`@layer` floor).
- `SCHEMA_VERSION` stays **2**. This delivery introduces no migration: the new fields are optional, with defaults resolved on read.
- Run `npm run lint` and `npx tsc -b --noEmit` before each commit. Run `npm test` on every verification step.
- Regenerate snapshots with `npx vite-node scripts/regenerate-snapshots.ts`. The `-e` flag does **not exist** in vite-node.
- Resolve paths in tests with `node:path` + `fileURLToPath`. The vitest in this repo runs jsdom, where `new URL(rel, import.meta.url)` resolves to `http://localhost:3000/...` and the following `readFileSync` reads the wrong file.

## Method warning, learned in the previous delivery

Six times the reference code of a plan in this project shipped a real defect that the plan's own tests did not catch, because the tests carried the same blind spots as the code. The most expensive case: every base-layer rule was tested with `pre code`, the only selector for which the wrong behavior was indistinguishable from the right one.

**Treat the code in this plan as a proposal, not as truth.** Before transcribing, build an input the plan did not foresee and run against it. When writing a test, ask whether it would also pass with the wrong code.

## One specific lesson this delivery must respect

The previous delivery broke `pre code` because it promoted rules to `@layer base` wrapped in `:where()`, and layer beats specificity unconditionally — so the rule lost to `code` in the `elements` layer. **Every rule you add to the base layer inherits that risk.** The scroll rules are safe because they touch properties no element rule defines today (`scrollbar-*`, `scroll-behavior`, `overscroll-behavior`), but confirm that instead of assuming: if a scroll property is also defined in `layers.elements` for the same target, the base version loses.

### Task 1: Emitting the scroll rules for `html`

The scroll tokens have been emitted on `:root` since the previous delivery, but no rule consumes them. This task closes that for the default target.

The delicate point is compatibility, not style: **on Chrome 121 and above, setting `scrollbar-color` disables the `::-webkit-scrollbar` pseudo-elements.** Emitting both side by side loses the rich parts. The correct output gives the parts to Chromium/WebKit and the standard properties to those without them, and **only** `scrollbar-color` and `scrollbar-width` go into the conditional block — the rest are standard in every engine.

- Modify: `tests/snapshots/presets/*.css` (regenerated)

**Interfaces:**

- Consumes: `Theme` from `src/theme/schema.ts`
- Produces: `scrollRules(theme: Theme): string[]`

`src/compiler/scrollRules.ts`:

```ts
import type { Theme } from '../theme/schema'

/**
 * Regras de rolagem para um alvo. Envolvidas em `:where()` porque vivem na
 * camada base, junto das demais regras-base.
 *
 * A separacao entre o que vai no gate e o que nao vai e de compatibilidade,
 * nao de estilo: no Chrome 121+ definir `scrollbar-color` DESATIVA os
 * pseudo-elementos `::-webkit-scrollbar`. Entao as partes ricas vao para
 * Chromium/WebKit, e apenas `scrollbar-color`/`scrollbar-width` ficam atras de
 * `@supports not selector(::-webkit-scrollbar)`, para quem nao tem as partes.
 * As demais propriedades sao padrao em todos os motores e vao sem gate.
 */
function rulesForTarget(target: string): string[] {
  const w = `:where(${target})`
  return [
    `${w} {\n  overscroll-behavior: var(--overscroll-behavior);\n  scroll-behavior: var(--scroll-behavior);\n  scroll-padding-top: var(--scroll-padding-top);\n  scrollbar-gutter: var(--scrollbar-gutter);\n}`,
    `${w}::-webkit-scrollbar {\n  height: var(--scrollbar-size);\n  width: var(--scrollbar-size);\n}`,
    `${w}::-webkit-scrollbar-track {\n  background: var(--scrollbar-track);\n}`,
    `${w}::-webkit-scrollbar-thumb {\n  background: var(--scrollbar-thumb);\n  border-radius: var(--scrollbar-radius);\n}`,
    `${w}::-webkit-scrollbar-thumb:hover {\n  background: var(--scrollbar-thumb-hover);\n}`,
    `@supports not selector(::-webkit-scrollbar) {\n  ${w} {\n    scrollbar-color: var(--scrollbar-thumb) var(--scrollbar-track);\n    scrollbar-width: var(--scrollbar-width);\n  }\n}`,
  ]
}

export function scrollRules(theme: Theme): string[] {
  void theme
  return rulesForTarget('html')
}
```

```ts
export function scrollRules(theme: Theme): string[] {
  // `??` e nao `||`: uma lista vazia e uma escolha legitima (nenhum alvo),
  // enquanto ausente significa o padrao. A constante e importada de
  // scrollDefaults para nao existirem duas fontes de verdade do mesmo padrao.
  const declared = theme.scrollTargets ?? defaultScrollTargets
  // Dedup preservando a ordem declarada: a saida precisa ser deterministica, e
  // um alvo repetido emitiria a mesma regra duas vezes.
  const targets = [...new Set(declared)]
  return targets.flatMap(rulesForTarget)
}
```

### Task 3: Reduced motion and print

Both blocks are emitted **outside any layer**, on purpose. Reduced motion is an accessibility decision that must not be accidentally overridable; and CSS without a layer beats CSS in a layer, so placing it inside `@layer` would make it weaker than any consumer rule.

`src/compiler/motionAndPrint.ts`:

```ts
import type { Theme } from '../theme/schema'

/**
 * Emitido FORA de qualquer camada, de proposito. CSS sem camada vence CSS em
 * camada, entao por dentro de `@layer` este bloco seria mais fraco que
 * qualquer regra escrita por quem consome o tema — o oposto do que uma
 * decisao de acessibilidade exige.
 */
export function reducedMotionBlock(theme: Theme): string {
  if (!theme.options.reducedMotion) return ''
  return `@media (prefers-reduced-motion: reduce) {
  :where(html) {
    scroll-behavior: auto;
  }
  :where(*, *::before, *::after) {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: .01ms !important;
  }
}`
}

/**
 * Conjunto opinativo e desligavel. Assume um documento de conteudo: fundo
 * branco, sem sombra, navegacao oculta, href revelado, e quebra de pagina
 * evitada dentro de titulo, figura e tabela.
 */
export function printBlock(theme: Theme): string {
  if (!theme.options.includePrintStyles) return ''
  return `@media print {
  :where(html) {
    background: #fff;
    color: #000;
  }
  :where(nav, aside) {
    display: none;
  }
  :where(*) {
    box-shadow: none !important;
  }
  :where(a[href^="http"])::after {
    content: " (" attr(href) ")";
    font-size: 0.85em;
    word-break: break-all;
  }
  :where(h1, h2, h3, h4, h5, h6) {
    break-after: avoid;
  }
  :where(figure, table, pre, blockquote) {
    break-inside: avoid;
  }
}`
}

export function motionAndPrint(theme: Theme): string[] {
  return [reducedMotionBlock(theme), printBlock(theme)].filter(Boolean)
}
```
