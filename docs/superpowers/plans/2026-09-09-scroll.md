# Scroll — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tornar o estilo de rolagem um recurso de primeira classe do tema exportado — barra, comportamento, âncoras e snap — junto com os blocos de movimento reduzido e impressão.

**Architecture:** Os tokens de scroll já existem no schema desde a entrega anterior, emitidos no `:root` mas sem consumidor. Esta entrega adiciona um módulo de compilador que os consome, gerando as regras de barra por alvo com o gate `@supports` que separa Chromium/WebKit de quem tem só as propriedades padrão; um módulo separado para os blocos de movimento reduzido e impressão, ambos emitidos **fora** de qualquer camada; e o painel Scroll no editor, com amostra rolável embutida.

**Tech Stack:** TypeScript 5.8, React 19, Zustand 5, Vite 7, Vitest 3, Playwright 1.55.

**Spec:** `docs/superpowers/specs/2026-09-08-css-editor-expansion-design.md` — seção "Tokens de scroll", "Compatibilidade da barra de rolagem" e "Movimento reduzido".

## Global Constraints

- As invariantes 1 a 6 de `docs/ARCHITECTURE.md` permanecem. Em particular: `src/compiler/**` não importa React nem usa API de browser (`document`, `window`, `localStorage`).
- CSS gerado é determinístico: mesmo tema, mesmos bytes. Todo teste de compilador deve poder compilar duas vezes e comparar.
- Declarações são ordenadas alfabeticamente pelo nome kebab dentro de cada regra; seletores seguem ordem canônica de domínio e depois `localeCompare`.
- Alvo de browser do CSS gerado: Chrome/Edge 99+, Firefox 97+, Safari 15.4+ (piso do `@layer`).
- `SCHEMA_VERSION` continua **2**. Esta entrega não introduz migração: os campos novos são opcionais, com padrão resolvido na leitura.
- Rodar `npm run lint` e `npx tsc -b --noEmit` antes de cada commit. Rodar `npm test` em todo passo de verificação.
- Regenerar snapshots com `npx vite-node scripts/regenerate-snapshots.ts`. A flag `-e` **não existe** no vite-node.
- Resolver caminho em teste com `node:path` + `fileURLToPath`. O vitest deste repo roda jsdom, onde `new URL(rel, import.meta.url)` resolve para `http://localhost:3000/...` e o `readFileSync` seguinte lê o arquivo errado.

## Uma lição específica que esta entrega precisa respeitar

A entrega anterior quebrou `pre code` porque promoveu regras para `@layer base` envolvidas em `:where()`, e camada vence especificidade incondicionalmente — então a regra perdeu para `code` na camada `elements`. **Toda regra que você adicionar à camada base herda esse risco.** As regras de scroll são seguras porque tocam propriedades que nenhuma regra de elemento define hoje (`scrollbar-*`, `scroll-behavior`, `overscroll-behavior`), mas confirme isso em vez de presumir: se uma propriedade de scroll também for definida em `layers.elements` para o mesmo alvo, a versão da base perde.

`src/compiler/scrollRules.ts`:

```ts
import type { Theme } from '../theme/schema'

/**
 * Regras de rolagem para um alvo. Envolvidas em `:where()` porque vivem na
 * camada base, junto das demais regras-base.
 *
 * A separacao entre o que vai no gate e o que nao vai e de compatibilidade,
 * nao de estilo: no Chrome 121+ definir `scrollbar-color` DESATIVA os
 * pseudo-elementos `::-webkit-scrollbar`. Entao as partes ricas vao para
 * Chromium/WebKit, e apenas `scrollbar-color`/`scrollbar-width` ficam atras de
 * `@supports not selector(::-webkit-scrollbar)`, para quem nao tem as partes.
 * As demais propriedades sao padrao em todos os motores e vao sem gate.
 */
function rulesForTarget(target: string): string[] {
  const w = `:where(${target})`
  return [
    `${w} {\n  overscroll-behavior: var(--overscroll-behavior);\n  scroll-behavior: var(--scroll-behavior);\n  scroll-padding-top: var(--scroll-padding-top);\n  scrollbar-gutter: var(--scrollbar-gutter);\n}`,
    `${w}::-webkit-scrollbar {\n  height: var(--scrollbar-size);\n  width: var(--scrollbar-size);\n}`,
    `${w}::-webkit-scrollbar-track {\n  background: var(--scrollbar-track);\n}`,
    `${w}::-webkit-scrollbar-thumb {\n  background: var(--scrollbar-thumb);\n  border-radius: var(--scrollbar-radius);\n}`,
    `${w}::-webkit-scrollbar-thumb:hover {\n  background: var(--scrollbar-thumb-hover);\n}`,
    `@supports not selector(::-webkit-scrollbar) {\n  ${w} {\n    scrollbar-color: var(--scrollbar-thumb) var(--scrollbar-track);\n    scrollbar-width: var(--scrollbar-width);\n  }\n}`,
  ]
}

export function scrollRules(theme: Theme): string[] {
  void theme
  return rulesForTarget('html')
}
```

```ts
export function scrollRules(theme: Theme): string[] {
  // `??` e nao `||`: uma lista vazia e uma escolha legitima (nenhum alvo),
  // enquanto ausente significa o padrao. A constante e importada de
  // scrollDefaults para nao existirem duas fontes de verdade do mesmo padrao.
  const declared = theme.scrollTargets ?? defaultScrollTargets
  // Dedup preservando a ordem declarada: a saida precisa ser deterministica, e
  // um alvo repetido emitiria a mesma regra duas vezes.
  const targets = [...new Set(declared)]
  return targets.flatMap(rulesForTarget)
}
```

`src/compiler/motionAndPrint.ts`:

```ts
import type { Theme } from '../theme/schema'

/**
 * Emitido FORA de qualquer camada, de proposito. CSS sem camada vence CSS em
 * camada, entao por dentro de `@layer` este bloco seria mais fraco que
 * qualquer regra escrita por quem consome o tema — o oposto do que uma
 * decisao de acessibilidade exige.
 */
export function reducedMotionBlock(theme: Theme): string {
  if (!theme.options.reducedMotion) return ''
  return `@media (prefers-reduced-motion: reduce) {
  :where(html) {
    scroll-behavior: auto;
  }
  :where(*, *::before, *::after) {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: .01ms !important;
  }
}`
}

/**
 * Conjunto opinativo e desligavel. Assume um documento de conteudo: fundo
 * branco, sem sombra, navegacao oculta, href revelado, e quebra de pagina
 * evitada dentro de titulo, figura e tabela.
 */
export function printBlock(theme: Theme): string {
  if (!theme.options.includePrintStyles) return ''
  return `@media print {
  :where(html) {
    background: #fff;
    color: #000;
  }
  :where(nav, aside) {
    display: none;
  }
  :where(*) {
    box-shadow: none !important;
  }
  :where(a[href^="http"])::after {
    content: " (" attr(href) ")";
    font-size: 0.85em;
    word-break: break-all;
  }
  :where(h1, h2, h3, h4, h5, h6) {
    break-after: avoid;
  }

  return [reducedMotionBlock(theme), printBlock(theme)].filter(Boolean)
```
